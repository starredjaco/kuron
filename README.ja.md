## なぜ作ったか

学生の個人開発者です。AI のおかげで、動くものに限れば、手で書いていた頃より何倍も速くプロトタイプを作れるようになりました。
それでも、さまざまなアイデアや市場のニーズを頭の中や計画書だけで思い描くのは、個人には難しいと感じています。
モックでは足りません。画面は簡単で、役に立つかどうかを決めるのは、その裏のふるまいだからです。

そこで kuron は順番を逆にしました。**先に、中身のあるもので試す。そのあとで作る。** 名前は日本語の「空論」から来ています。

## 使い方

1. **アイデアを書く**：言葉で書くだけです。一言でも、1ページでも構いません。どの言語でも使えます。
2. **触って確かめる**：AI が、端末や役割ごとに最小限の画面を用意します。そのうえで、普通の開発なら一番時間のかかる
   バックエンドや、データ、画面どうしのつなぎを、AI がシステムとして演じます。ボタンを押すたびに AI が処理します。
   アプリのコードは生成しません。
3. **逆算する**：気に入ったら、実際に動いた内容を正解例にした仕様と、作業の計画、コーディングエージェントに渡すプロンプトを
   書き出します。動画の診療所の場合、本気で作ると約92時間という見積もりでした。

## できること

- **複数の端末が、ひとつの状態を共有**：受付のタブレット、診察室のパソコン、患者のスマホ、待合室の表示板が同じデータを
  見ているので、ひとつの操作がすべての画面に反映されます。
- **話しかけて直す**：「緊急度の理由も出して」と頼むと、AI が自分の画面とふるまいを書き換えます。
- **既存技術スイッチ**：AI を使うと、どんなアイデアも簡単そうに見えてしまいます。そこで AI が、操作ごとに
  「いま出せる版なら何で作るか（普通のコード / AI モデル / 外部サービス / 今は無理）」「どれくらい間違えるか・遅れるか」を
  見積もり、スイッチを入れると試作がそのとおりに振る舞います。
- **検証**：人が使う場面のシナリオを、システムのコピーの上で実行して判定します。
- **逆算**：仕様・正解例・作業の計画・プロンプトを出力します。
- **現実の部品**：試しの音、イヤホン向けの音の加工、読み上げ、図、画像。
- **フォーム以外の画面。** アイデアの見た目は AI が選びます。ふつうの部品、AI 自身が HTML と CSS で書くページ、
  押す・ドラッグする・キーで操作できる絵、そしてステージ（AI が宣言した物体と反射の規則を端末が毎フレーム動かし、
  レベルクリアやポーズ判定など意味のあることだけを AI に知らせる）。
- **先読み**（既定はオフ）。誰も押していない間に、次に押せるものの結果を AI が世界のコピーの上で先に演じておき、
  準備ができていれば押した瞬間に反映します。そのぶん AI を多く使います。

## ほかのツールとの違い

| | UI・アプリ生成ツール（Lovable、v0、Figma Make など） | kuron |
|---|---|---|
| できあがるもの | 画面とアプリのコード | 最小限の画面。ふるまいは AI がその場で演じる |
| 判断やバックエンドの処理 | コードが必要。試作では固定のデータでごまかすことが多い | AI が実際に判断する（優先順位、おすすめ、経路、見積もり） |
| まだ存在しない技術 | つなぐまで動かない | AI がその部分を演じる |
| 複数の役割・端末 | 画面ごとに作る | ひとつの状態を共有する |
| 直し方 | コードを直す | 「ここはこうして」と言う |
| 本当に作れるか | 作ってみないと分からない | 操作ごとに見積もり、スイッチで体験できる |
| 手元に残るもの | コード | 仕様・正解例・プロンプトつきの開発計画 |

**向いていないこと**：本番での利用（1回の操作に数秒と数セントかかり、結果も毎回わずかに揺れる）、ピクセル単位の UI
デザイン、ゲームなどの即座の反応が要るもの、大量で厳密なデータ処理。

## 自分のパソコンで動かす

```bash
npx github:Ag3497120/kuron try
```

例を `./kuron-examples` にコピーして、http://127.0.0.1:4870/ を開きます。Node.js 20 以上と、次のどれか1つが必要です：
ログイン済みの [Claude Code](https://claude.com/claude-code)、下の表のいずれかの API キー、または [Ollama](https://ollama.com)。

| モデル名 | 動く場所 | 必要なもの |
|---|---|---|
| `claude-…`（標準） | Claude Code（`claude -p`、道具は MCP サーバーとして渡す） | ログイン済みの Claude Code |
| `codex:<model>` | Codex CLI（`codex exec`、道具は MCP サーバーとして渡す） | ログイン済みの Codex CLI |
| `anthropic:<model>` | Anthropic API | `ANTHROPIC_API_KEY` |
| `openai:<model>` | OpenAI、または `KURON_OPENAI_BASE_URL` で指定した互換サーバー | `OPENAI_API_KEY` |
| `gemini:` · `openrouter:` · `groq:<model>` | 各社の OpenAI 互換 API | `GEMINI_API_KEY` · `OPENROUTER_API_KEY` · `GROQ_API_KEY` |
| `lmstudio:<model>` | このパソコンの LM Studio | なし |
| それ以外 | このパソコンの Ollama | Ollama |

開発画面では、上のバーのモデル名を押すと設定が開きます。セットアップ用とボタン操作用のモデルを、動かしたまま上のどれにでも切り替えられます。

```bash
kuron try --preset anthropic                                       # Anthropic API で動かす
kuron try --compile-model openai:<model> --cpu-model openai:<small> # 好きなプロバイダで動かす
kuron dev .                    # フォルダ内のアイデアを開く。「＋ 新しく作る」で一言から
kuron new "診療所の受付を…"     # アイデアを書いて立ち上げる
kuron check idea.kuron         # 検証を実行する
kuron hands --url <host>       # 道具を MCP サーバーとして、ほかの MCP クライアントから使う
```

ブラウザ版とローカル版の違い：ブラウザ版は claude.ai へのログインだけで使えます。マイクは使えず、タイマーはボタンで1回ずつ
動かします。ソースは `web/` にあります（`node tools/build-web.mjs` でまとめます）。

## 守っているルール

| コードに入れるもの | コードに入れないもの |
|---|---|
| 汎用の道具（データの保存と読み出し、画面の定義、通知、音、読み上げ、図、タイマー、検証、見積もり）、すべての道具の呼び出しの形を確かめて言葉で返すチェック、最小限の描画 | 業務の判断、単語のリスト、AI の意図の推測、特定のアイデアのための例外 |

うまく合わないときは、道具が AI に何が違うかを伝え、AI が自分で直します。試作の動きがおかしいときは、どう振る舞うべきかを
AI に伝えます。設計の詳細は [docs/DESIGN.md](docs/DESIGN.md)（英語）にあります。

## アイデアを共有してください

kuron は、試すアイデアがまだ足りていません。特に kuron が壊れるようなアイデアは大歓迎です。`examples/<名前>.kuron` として
プルリクエストを送るか、うまくいった点・壊れた点を Issue に書いてください（ブラウザ版の「フィードバック」ボタンからも
送れます）。詳しくは [CONTRIBUTING.md](CONTRIBUTING.md)（英語）を見てください。
